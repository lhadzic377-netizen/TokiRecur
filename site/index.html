The mechanism

Every request is compared against the KV blocks already in memory.

Token by token. The longest identical prefix is replayed instead of recomputed. There is no second model, no separate cache server, no client change.

Everything in the package.

The daemon is only half of it. These are the parts you get on the same install.

  • Drop-in cache

    Point any OpenAI-compatible client at the toki daemon. Prompts that share a prefix return instantly.

  • Live reuse

    Multiple agents and shells share one server's KV cache. Context written by one session is replayed by the next.

  • Save & restore

    Snapshot caches to disk and restore them later: cold-start with a long system prompt already cached, or hand a session to another machine.

  • RAM-aware by default

    The daemon reads the GGUF header, fits the KV cache into the machine's memory, and advertises the real context to clients.

  • Benchmark harness

    Run real workloads, agent loops, RAG chunks, adversarial prompts, and report cache-hit rates vs. a fresh cache.

  • TUI + web chat

    Full-screen terminal chat and a production-ready single-page web UI ship with the package, one command each.

Three commands from cold start to a shared cache.

Boot the stack, wire your clients at the daemon, and let the prefix matcher do the rest.

  1. Boot, toki model use starts llama-server plus the toki daemon, wires your CLI tools at it, and writes the effective context it can actually hold.
  2. Stream, clients call the daemon's OpenAI-compatible API. Shared prefixes hit the cached KV blocks instead of re-running the model.
  3. Persist, toki cache save / toki cache restore snapshot caches to disk; toki cache stats shows hits, misses, and savings.

Platforms

Where it runs.

Toki Recur is pure Python over the llama-server HTTP API. It runs on any x86_64 or aarch64 device running Linux, macOS or Windows, with whatever GPU backend your llama-server build has.

PlatformArchllama-server backendsStatus
Linuxx86_64 CUDA (auto NVIDIA) · ROCm (auto AMD/HIP) · SYCL (explicit Intel Arc) · OpenVINO (explicit Intel) · Vulkan · CPU stable
Linuxaarch64 CUDA (auto NVIDIA) · Vulkan · CPU stable
macOSx86_64, arm64 Metal (one universal build; runs CPU-only with -ngl 0) stable
Windowsx86_64 CUDA (auto NVIDIA) · SYCL (auto Intel Arc) · Vulkan (auto AMD) · ROCm/HIP (explicit AMD) · OpenVINO (explicit Intel) · CPU beta
Windowsaarch64 CUDA (auto NVIDIA) · Vulkan · CPU beta

Every GPU install verifies the vendor runtime and a real device line from llama-server --list-devices before reporting success, so a missing driver cannot silently degrade to CPU.

Mascot

Meet toki.

toki is the mascot of Toki Recur, the bear who recurs. He wears the recycle symbol because the whole product is one idea: don't recompute what you've already read. Long system prompts, RAG corpora, agent tool definitions, all get computed once, then streamed from cache on every subsequent request.

He's here to remind you that cache reuse is the boring superpower underneath every fast local model.

Install and run.

Nothing is preinstalled. Clone, run the installer, pull one model, open the launcher.

macOS / Linux

git clone https://github.com/lhadzic377-netizen/TokiRecur.git
cd TokiRecur
./install.sh
toki model pull Qwen/Qwen3-4B-GGUF --use
toki

Windows (cmd or PowerShell)

git clone https://github.com/lhadzic377-netizen/TokiRecur.git
cd TokiRecur
install.bat
toki model pull Qwen/Qwen3-4B-GGUF --use
toki

Supported today: x86_64 and arm64 Linux and macOS are stable; Windows is beta. GPU support depends on the llama-server backend you install. The docs have the full platform and backend matrix. Optional systemd/launchd daemon mode is included. The macOS/Linux installer runs behind a yellow progress bar while the real output still streams live.

A note on compatibility

Some models work. Some need a tweak. I'm honest about it.

toki model pull accepts every GGUF on Hugging Face, so the answer to "does this model work?" depends on the model, the quant, and your hardware. Some GGUFs boot clean and chat on the first try. Others need a chat template swap, a smaller context, a different quant, or a small edit to the registry. I test what I recommend and fix what I ship, but I won't pretend every combination works the same.

It will keep getting better. The failure modes I hit this week (broken chat templates, runtime crashes on a quant, ETXTBSY on a binary swap) feed the next round of fixes. Better auto-detection, fewer surprises, more recovery paths baked in. The project is MIT licensed, and the path from "this model is broken" to "this model works" is one fix away.

Tested on a small set of machines: AMD Strix Halo (Linux), M2 (macOS), Intel i7-8650U (Windows), Intel Core Ultra 155U (Linux), GTX 1650 Mobile (Windows). That's five configs, not a hardware matrix. Different GPU, different VRAM, different kernel, different driver; any one of them can change the outcome. That's where the next bug report usually comes from.
