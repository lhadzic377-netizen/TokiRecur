Install

Toki Recur is a Python app, install it with pipx, which isolates it in its own venv and puts toki on PATH. While the repo is private, the install URL carries a read-only token (a fine-grained PAT with Contents: read on lhadzic377-netizen/TokiRecur only). The token appears in your shell history; that's the private-repo tax.

Simplest: clone, then run the installer

Clone the repo once (your Git credentials do the auth) and run the installer from the checkout. Cross-platform, no token required.

# Linux / macOS
git clone https://github.com/lhadzic377-netizen/TokiRecur.git
cd TokiRecur
./install.sh
:: Windows (cmd or PowerShell)
git clone https://github.com/lhadzic377-netizen/TokiRecur.git
cd TokiRecur
install.bat

Both install the toki CLI with pipx (auto-installed if missing; Linux/macOS falls back to a venv). The embeddings extra (sentence-transformers + torch) is included by default; skip it with TOKI_EXTRAS= ./install.sh.

Direct pipx install

pipx install "tokirecur[embeddings] @ git+https://x-access-token:<PAT>@github.com/lhadzic377-netizen/TokiRecur.git"

One-time: sudo apt install pipx or python3 -m pip install --user pipx.

Without pipx

Install into your own venv instead:

python3 -m venv .venv && source .venv/bin/activate
pip install "tokirecur[embeddings] @ git+https://x-access-token:<PAT>@github.com/lhadzic377-netizen/TokiRecur.git"

If toki is not found after install, your PATH may not include the venv's bin directory, either activate the venv or use the full path (./.venv/bin/toki). On systems where pip install -e writes a shim to ~/.local/bin that points at system Python, delete that shim and re-run pip install -e . from inside the activated venv so the shim is regenerated with the correct shebang.

curl / irm one-liner installers

While the repo is private, fetching the installer and the package itself requires a token. Always pass it via the environment, never hardcode tokens in scripts or workflow files, never pass them as CLI arguments (they'd be visible in the process list), and scope them to the minimum (a fine-grained PAT with Contents: read on lhadzic377-netizen/TokiRecur only). The installers below are the scripts scripts/install-curl.sh and scripts/install-irm.ps1, fetched securely from the private repo and run locally, they install tokirecur via pipx using TOKI_REPO_TOKEN.

Linux / macOS (curl)

export TOKI_REPO_TOKEN="ghp_..."   # fine-grained PAT, Contents: read
curl -sf -H "Authorization: Bearer $TOKI_REPO_TOKEN" \
  -H "Accept: application/vnd.github.raw" \
  "https://api.github.com/repos/lhadzic377-netizen/TokiRecur/contents/scripts/install-curl.sh" \
  -o /tmp/toki-install.sh
bash /tmp/toki-install.sh

Windows (irm / PowerShell)

$env:TOKI_REPO_TOKEN = "ghp_..."
$installer = irm -Uri "https://api.github.com/repos/lhadzic377-netizen/TokiRecur/contents/scripts/install-irm.ps1" `
  -Headers @{ Authorization = "Bearer $env:TOKI_REPO_TOKEN"; Accept = "application/vnd.github.raw" } -ErrorAction Stop
$installer | Out-File -Encoding utf8 "$env:TEMP\toki-install.ps1"
pwsh -File "$env:TEMP\toki-install.ps1"

curl -sf (exit code 22 on HTTP errors) and irm ... -ErrorAction Stop fail fast on auth errors instead of silently downloading an error page. Both installers read the token from TOKI_REPO_TOKEN (or GITHUB_TOKEN) and refuse to run without it. After local testing, clear it: unset TOKI_REPO_TOKEN / Remove-Item Env:\TOKI_REPO_TOKEN.

Fetch the llama-server binary

One command installs the matching official build, it auto-detects the best backend for your machine. Pass --backend to override.

toki model install-llama                 # auto-detect backend, latest release
toki model install-llama --backend rocm  # force a backend (rocm|cuda|sycl|vulkan|metal|cpu)
toki model install-llama --backend rocm --gfx 11.5.1  # set HSA_OVERRIDE_GFX_VERSION
toki model install-llama --tag b6400     # pin a release tag
toki model install-llama --name 35b      # ...and point a registry model at it

Platforms

Toki Recur is pure Python over the llama-server HTTP API, it runs on any x86_64 or aarch64 device running Linux, macOS or Windows, with whatever GPU backend your llama-server build has. The only per-platform piece is the llama-server binary itself:

PlatformArchitecturellama-server builds
Linuxx86_64ROCm (auto if HIP present), Vulkan, CPU
Linuxaarch64Vulkan, CPU
macOSx86_64, arm64Metal (also runs CPU-only)
Windowsx86_64CUDA (auto NVIDIA), SYCL (auto Intel Arc), Vulkan (auto AMD), ROCm/HIP (explicit AMD), CPU
Windowsaarch64Vulkan, CPU

The GPU backends are provided by the llama-server binary itself, Toki Recur talks to it over HTTP and is backend-agnostic. On Windows every GPU install verifies the vendor runtime DLLs and a real device line from llama-server --list-devices before reporting success, so a missing driver cannot silently degrade to CPU.

System daemon installers

Optional, run as a system daemon (dedicated user + service manager unit + log rotation, auto-start at boot). install.sh/install.ps1 bootstrap the full stack themselves (own venv at /opt/toki-recur, package + llama-server + service unit), so they work standalone, they don't need the pipx install above:

# Linux  -> systemd + logrotate   (macOS -> launchd LaunchDaemon)
sudo ./install.sh

# Windows (PowerShell): install.ps1; then `toki serve` yourself or wrap
# it in NSSM / a scheduled task.

Model registry

Or point binary: at any llama-server on PATH in the registry (~/.config/tokirecur/models.yaml). Override locations per-machine with TOKI_MODEL_REGISTRY (config) and TOKI_STATE_DIR (logs/pid/bin). On Windows the systemd service commands are unavailable (reported cleanly); the RAM guard uses GlobalMemoryStatusEx, and on macOS the UMA/RAM guard uses sysctl hw.memsize.
